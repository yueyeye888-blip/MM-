# 做市表格实时监控系统 V3.2

本地只读旁路监控：WPS Excel 仍是唯一业务录入入口，本系统不回写、不保存、不关闭也不锁定工作簿。

## 现在运行（推荐）

双击桌面上的 `启动APR监控.command`。启动器会同时启动：

- 做市表格监控 Agent：`127.0.0.1:8765`
- WPS Bridge 页面服务：`127.0.0.1:3889`
- 本地监控看板

首次安装 Bridge 后，需要完整退出并重新打开 WPS 一次，让 WPS 读取加载项配置。启动器不会强制关闭 WPS，也不会触碰未保存文档。

也可以只启动 Agent：

```bash
cd "/Users/xingxiu/Desktop/MM表格数据汇报"
chmod +x run.sh
./run.sh
```

然后访问 <http://127.0.0.1:8765>。API 文档位于 <http://127.0.0.1:8765/docs>。

首次启动会自动把桌面的 `APR_做市实时表_V3_美化版.xlsx` 注册为 APR 项目，并沿用原数据库。之后可在页面右上角“管理项目”中：

- 注册 WPS 当前打开的兼容表格；
- 浏览桌面目录并选择 `.xlsx/.xlsm`；
- 同时监控多个项目，在顶部下拉框切换查看；
- 移除不再监控的项目；移除只停止监控并隐藏登记，原数据库与备份保留，重新注册同一表格会恢复原历史；
- 每个项目使用独立数据库和备份目录，历史互不污染。

## 监控模式

- `DISK_REALTIME`：默认模式，每 1 秒检查工作簿。WPS 点击保存后立即重读完整 xlsx，不依赖 Bridge。
- `WPS_MEMORY`：可选模式，用于获取未保存值；不影响手动保存后的磁盘实时监控。

Bridge 诊断地址：<http://127.0.0.1:8765/api/v1/bridge/status>。其中 `event_registered=true`、`connected=true` 且 `mode=WPS_MEMORY` 才表示未保存值通道生效。

## 已实现

- 按列标题动态识别现货/合约账户，新增账户无需改代码。
- Raw Event、3 秒稳定窗口、SQLite WAL 快照、现货成本与已实现利润、合约均价/盈亏。
- 项目汇总、净敞口、综合盈亏平衡价、1/5/10 分钟净变化。
- 总可用资金（启用现货+合约账户的“现有资金”合计）、现货总收益、合约总收益与项目总收益。

收益口径：

- 现货总收益 = 现货可用资金 + 现货市值 - 现货累计投入。
- 合约总收益 = 合约现有资金 - 合约累计投入 + 合约未实现收益。
- 项目总收益 = 现货总收益 + 合约总收益。
- 纠错标记消费、异常状态、监控健康、手动/整点纯文件备份。
- 本地 Web 看板、账户明细与确定性对话查询。

## 启动检测

页面“启动检测”采用任务和时段两层结构：

1. 输入任务名称，点击“开始检测”；点击瞬间的数据是基准值。
   检测区域会始终显示当前项目、工作簿文件名、完整路径和工作表。
2. 点击“停止当前时段”后自动生成开始值、结束值、净变化、账户变化和全部中间事件。
3. 稍后可从下拉框选择原任务再次开始，新时段会继续归入原任务。
4. 勾选任意多个已停止时段，点击“合并所选时段”生成确定性合并报告。
5. Bridge 离线或监控中断不会删除报告，但会明确标记“数据存在监控缺口”。

时段报告只展示变化指标，不显示累计投入、现货价格和合约价格。现货数量、可用资金、市值等均明确标记为“变化”。报告另外提供现货持仓成本变化与分阶段买入成本。

“现货持仓总均价”是表格直接口径，固定读取 `APR实时表!G7:H7` 合并单元格的锚点 `G7`。该值与系统根据历史变动推导的内部持仓成本均价分开，对话和看板不得混用。

数据对话会按项目永久保存问题、回答、模板、模型与时间；页面重新加载或切换项目时会恢复该项目全部历史。旧版本仅保存过问题的记录也会保留展示，但无法恢复当时未入库的回答。

## GPT 数据对话

数据对话使用 OpenAI Responses API，分为两种模式：

- 回答模板（推荐）：选择当前快照、最近检测或勾选时段。后端先确定性取数和合并，然后只进行一次 GPT 请求，速度和格式更稳定。
- 自由问答：模型按问题调用本地受控数据工具，适合临时、非固定问题。

现货成本口径由本地成本引擎确定性计算：买入时按扣除追加资金影响后的现有资金减少额增加持仓成本，卖出时按历史成本均价释放持仓成本。GPT 必须读取该结果，不得用当前现货市价代替持仓成本均价或阶段买入均价。

所有名称中包含“均价”的数据统一固定显示小数点后 5 位；该规则由后端和页面共同强制执行，不依赖 GPT 自行决定精度。

点击“编辑模板”可以自定义字段、顺序、标题、单位、语气、篇幅，以及是否包含账户变化和全部中间事件。模板保存在本地 `data/chat_templates.json`，后续可继续修改。系统内置当前盘面简报、最近检测汇报和勾选时段合并汇报。

首次使用：

1. 在 OpenAI API 平台创建 API Key 并开通独立 API 计费。
2. 在看板“数据对话 → API 设置”粘贴 Key。
3. Key 只写入 macOS 钥匙串的 `APRMonitorOpenAI` 项，不写入源码、浏览器存储或数据库。

也可在启动前设置 `OPENAI_API_KEY`；模型可用 `OPENAI_MODEL` 环境变量覆盖，默认读取 `config.json` 的 `openai_model`（当前为 `gpt-5.6-terra`）。普通数据问答使用低推理，模板与阶段报告使用中等推理。未配置 Key 时，系统自动降级为原有本地规则回答。

## 数据目录

- 数据库：`data/apr_monitor.db`
- 项目注册表：`data/projects.json`
- 新项目数据库：`data/projects/<project_id>.db`
- 检测任务数据库：`data/control.db`
- 备份：`backups/`
- WPS Bridge：`wps-bridge/`

若要重新建立基线，请先停止程序，手工移动（不要直接删除）`data/apr_monitor.db` 后再启动。
